## API для соседей

```js
G.gfx = { tier, auto, set(t) }            // 0 — слабое железо, 2 — всё; событие 'gfx' {tier}
G.look = {
  post: true,                             // сцена не рисует свою виньетку, ночной тон и стартовую заливку
  a2, a2on, k, amb,                       // свет на актёрах; когда проход выключен, a2 = [1,1,1]
  glow(x, alt, r, rgb, a) → bool,         // заявка на свечение в этом кадре; rgb — 'r,g,b' | '#hex' | [r,g,b]
  at(x, alt) → 0..1,                      // сколько света в точке (лучи, свечения, полосы)
  rim: { rgb, a, dir, css },              // контурный свет кролика (dir: −1 спина, +1 морда, 0 сверху)
  lit,                                    // сглаженное at() у кролика
  ramp(hex) → { hi, base, shade, deep, line },
  lw(wu, px) → number,                    // толщина: max(wu, px / G.scale)
  debug: { fse, glows, tierLog, perf }, debugAt(clock),
};
G.locLooks = { id: { grade, gradeA, vig, vigA } }   // необязательный реестр look для локаций без def.look
```

- `G.look.glow`: пул на кадр 32 / 12 / 6 по уровню. Заявки, сделанные после слоя 67 (fx на 70+), рисуются в следующем кадре. Радиус в мировых единицах, alt — высота над `G.GROUND`.
- Формат `G.scene.lights`, на который рассчитан передний проход и `at()` (совпадает с тем, как его заполняет scene.js): `beam` — верх луча в `(x, y)`, ширина `w`, длина `h`, угол `ang` (рисуется `translate → rotate(−ang)`); `glow` — центр `(x, y)`, полный размер `w × h`; `strip` — центр верха `(x, y)`, ширина `w`, свет вниз на `h`.
- `look` локации: `grade` (`'#hex'`/`'rgb()'`), `gradeA` (≤ 0.2), `vig` (`[r,g,b]`), `vigA` — множитель альфы виньетки. Ищется в `G.scene.loc.look`, затем `G.locLooks[id]`, затем `G.locations[id].look`. Объект читается каждый кадр, поэтому его можно менять на лету (так делает сон).
- Слои B: 39 тень кролика, 60 кролик, **65** свет на актёрах, **65.5** контурный свет кролика, **66** передний свет, **67** свечения, **81** блик 17:59, **82** грейд → виньетка → зерно, **90.9** оверлей `?perf`.

## Правила стиля (сокращённо из design/visual.md, раздел 9)

- Насыщенный красный — только опасность, насыщенный оранжевый — только морковки. Декор в полосе игры (alt 0–170) не похож на будильник на ножках, стопку стикеров, тёмный ноутбук со светящимся экраном, висящую карточку, морковку — иначе параллакс ≤ 0.45 и хейз ≥ 25 %.
- Контур объекта — `G.look.ramp(самая тёмная заливка).line` с α 0.8, толщина `G.look.lw(1.6, 1.5)` у препятствий, `lw(1.3, 1.4)` у пикапов. У тёмных материалов (L* < 45) контур светлый: `ramp().hi` с α 0.35.
- Самосветящееся (экраны, лампы, морковки ночью) — через `G.look.glow`, а не `globalAlpha` поверх: так свечение не тонируется ambient и попадает в бюджет уровня.
- Без `shadowBlur` и `ctx.filter` в кадре; градиенты — только в кэше.

## Просьбы

1. В CONTRACT: `G.gfx`, `G.look` (API выше), событие `gfx`, слои 65 / 65.5 / 66 / 67 / 81 / 82 / 90.9, `G.locLooks`.
2. Smoke: при 30 и 25 к/с автовыбор честно опускает уровень до 0 за ~5 с, поэтому `play-desktop`, `chaos-desktop`, `phone-chaos` и марафон гоняют проходы уровня 2 только первые секунды. Уровень 2 покрывают планировщики на 60 к/с. Хорошо бы дать `runScenario` опцию `search` (сейчас `location.search` всегда пустой) и прогнать, например, марафон с `?gfx=2`. Проверить по пути: `G.look.a2` и `G.look.rim` конечны.
3. По желанию: `G.cfg.maxDpr` или `G.setRenderScale(k)` для уровня 0. Без этого B разрешение не трогает.

**Графика A (scene.js)** — уже совместимо: `G.look.post`, `a2`/`a1`, `emiK`, `lights` в том формате, что выше. Необязательно: класть `look` локации в `G.scene.loc.look` и `emiK` в `L` (сейчас B берёт `G.locations[id].look` и `kit.emiK`).

**Геймплей A (obstacles.js)** — по разделу 12 плана: контуры по `G.look.ramp/lw`, экраны ноутбука и созвона, бейдж пинга и лампа дедлайна через `G.look.glow` (ноутбук r 44 '159,211,255' a 0.8; созвон r 50 '176,200,255'; пинг r 20 '61,139,253'; дедлайн r 30 '255,59,48'), `groundShadow` в multiply с холодным тоном rgb(70,60,110).
